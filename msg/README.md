# File Structure

| File | Relevance | Dependencies | Used by |
| --- | --- | --- | --- |
| FirmwareTimingEvent.msg | Carries typed PPS, trigger-command, camera exposure-midpoint, and IMU SyncOut records. Exposure/IMU feedback includes the Teensy trigger counter within its relative MCU epoch; the relative epoch is not UTC, ROS time, or a hardware boot ID. | None | main/main.ino, scripts/teensy/timing_event_adapter.py |
| AcquisitionTimingEvent.msg | Carries identified Teensy PPS, trigger-command, camera exposure-feedback, IMU SyncOut, and per-camera frame events. Firmware events preserve the associated Teensy trigger counter and its source ID; camera frames preserve the full Spinnaker counter, raw device nanoseconds, driver stream UUID, and SDK-arrival host ROS/monotonic clocks. Explicit measured-correlation records can link a camera frame counter to its identified Teensy trigger or exposure event; the adapter never pairs them automatically from receipt time. Source-clock calibration remains unavailable until measured. | std_msgs/Header | scripts/teensy/timing_event_adapter.py; GRANDE timing records |
| ClockedImu.msg | Carries raw device time and a ROS timestamp; when the mapping is uncalibrated, the ROS timestamp is receipt-anchored rather than a measured acquisition epoch. Distinguishes the driver source instance from an explicitly unknown hardware boot ID, and carries receipt clocks, epochs, sequence identity, mapping revision, and uncertainty. | std_msgs/Header, sensor_msgs/Imu | scripts/imu/sample_clock.py, DLiO timing admission, simulator timing bridge |
| JkBmsDetails.msg | Carries the registered battery ID together with JK-specific hardware identity, provenance, cell-balance, cycle, alarm, and switch details alongside the standard `sensor_msgs/BatteryState` `/sense_ighandle` surface. | std_msgs/Header | scripts/power/jk_bms_node.py, recording and power diagnostics |
| Ping360RawPacket.msg | Defines timestamped raw Ping360 packet transport with publisher-session identity, explicit physical/synthetic provenance, and provider-specific extrinsic-revision provenance. | std_msgs/Header | scripts/sonar/ping360_provider.py, ig_handle/CMakeLists.txt |
| SonarDiagnostics.msg | Reports provider identity, endpoint, read-only state, protocol and firmware versions, packet counters, errors, timeouts, and configuration hash. | std_msgs/Header | scripts/sonar/ping360_provider.py, IG Handle readiness and recording consumers |
| SonarPlanarProfile.msg | Preserves source/session/capture and original-return identity, acquisition-frame and calibration references, declared source-versus-receipt/offset-estimate timing, and range/azimuth/intensity arrays with explicit extracted-return versus intensity-bin semantics. Planar products carry no measured elevation. | std_msgs/Header | MARINER DT100/Ping360 decoders, native marker/natural associations, recording |
| SonarProfile.msg | Defines provider-neutral sonar profile samples with receipt time, explicitly available acquisition time and uncertainty, distinct capture and publisher-session identities, content hash, physical-versus-synthetic, frame, and extrinsic revision. Physical acquisition phase remains unknown unless supplied. | std_msgs/Header | scripts/sonar/ping360_provider.py, mariner sonar imaging, heron_simulator Ping360 profiles, range_aid marker frontend, ig_handle/CMakeLists.txt |
| SonarRawPacket.msg | Preserves a sonar vendor datagram with ROS receipt time, optional acquisition time and known/unknown uncertainty, provider identity, restart-safe publisher-session plus sequence identity, explicit physical/synthetic provenance, source endpoint, packet kind, and extrinsic revision. The session ID is not a hardware boot ID. | std_msgs/Header | scripts/sonar/receiver.py, heron_simulator multibeam simulation, mariner DT100 decoder, ig_handle/CMakeLists.txt |

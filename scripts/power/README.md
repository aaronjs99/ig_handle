# File Structure

| File | Relevance | Dependencies | Used by |
| --- | --- | --- | --- |
| __init__.py | Declares the installed IG Handle power package. | Python | catkin Python packaging |
| battery_registry.py | Validates battery roles, durable asset labels, commissioning state, uniqueness, and the complete JK identity without using voltage, current, or inferred behavior as identity. | pathlib, yaml, config/sensors/battery_registry.yaml | JK BMS admission, GRANDE pack selection and validation |
| bluez_ble.py | Owns exact-address/name/service discovery, notification delivery, identity-gated read queries, telemetry-timeout detection, and reconnect behavior for the commissioned JK BMS. | BlueZ D-Bus, GLib | scripts/power/jk_bms_node.py |
| reconnect_guard.py | Provides the thread-safe, bounded protocol-error threshold and idempotent reconnect request used to recover from a connected device that repeatedly returns malformed or unsupported frames. | Python standard library | bluez_ble.py, jk_bms_node.py, validate_battery_registry.py |
| heron_sense_ingress.py | Republishes the admitted raw Heron MCU `Sense` stream on the canonical IG Handle topic after exact publisher and finite-value checks. | rospy, heron_msgs/Sense | GRANDE telemetry and actuator evidence paths |
| jk_bms_node.py | Holds a host-wide lock for the exact BLE address, admits identity before requesting telemetry, ignores pre-identity measurements, and publishes read-only battery state only while the live device matches the commissioned configuration and registered asset. | rospy, sensor_msgs/BatteryState, ig_handle/JkBmsDetails, battery_registry.py, bluez_ble.py, jk_bms_protocol.py | IG Handle power launch and GRANDE telemetry |
| jk_bms_protocol.py | Strictly assembles and decodes the explicitly selected JK02 24S/32S read-only frame layout with checksum, identity, cell-count, named alarm/status, and physical-plausibility checks. | Python stdlib | scripts/power/jk_bms_node.py and GRANDE power contracts |
| validate_battery_registry.py | Exercises registry uniqueness, commissioning separation, exact hardware matching, identity-first query admission, settings/telemetry response classification, reconnect behavior, timing constraints, and rejection of altered or unknown identity. | battery_registry.py, bluez_ble.py, jk_bms_protocol.py, config/validation/battery_registry_cases.yaml | Offline acceptance |

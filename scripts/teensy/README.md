# File Structure

| File | Relevance | Dependencies | Used by |
| --- | --- | --- | --- |
| build_firmware.sh | Stages the checked-in Teensy source and configuration, verifies the installed content-pinned ros_lib snapshot, generates the required custom message header from the clean rosserial source at `heron_ws/src/drivers/rosserial`, pins the Teensy 4.1 toolchain/libraries, embeds a portable source-bound build ID, and emits hashed ELF/HEX artifacts without flashing. The manifest records the pinned base ros_lib hash and generated timing-header hash separately. | Arduino CLI 1.3.0, Teensy core 1.60.0, RTClib 2.1.4, Adafruit BusIO 1.17.4, rosserial c169ae2, ros_lib bd37a406 | Source-checkout firmware build and commissioning record |
| teensy_rosserial_launcher.py | Bounds device startup, supervises a uniquely named rosserial child, and fail-stops on child exit, device loss, or missing, stale, or mismatched commissioned firmware identity. | rospy, rosserial_python, std_msgs, config/udev/99-ig-handle.rules | CMake installation, launch/core/start_rosserial.launch |
| timing_event_adapter.py | Converts typed Teensy trigger-command, exposure-feedback, IMU SyncOut, and PPS records, Spinnaker frame timing, and optional per-driver LiDAR cloud headers into acquisition-timing records. Teensy feedback records retain the trigger counter within the source clock epoch; this is not a cross-restart capture ID or a link to a Spinnaker frame counter. LiDAR headers remain explicitly unverified acquisition clocks. Firmware restart generations are inferred because no durable device boot ID is supplied; device-clock calibration remains unavailable until measured. | rospy, sensor_msgs/PointCloud2, ig_handle/FirmwareTimingEvent, spinnaker_camera_driver/CameraFrameTiming, ig_handle/AcquisitionTimingEvent | CMake installation, launch/core/start_timing_event_adapter.launch, launch/sensors/start_lidar.launch |
